Backup encryption

When enabled, new backups are encrypted (AES-256-GCM) with a key derived from the passphrase below before being written to the backup location - useful if the backup destination isn't fully trusted (e.g. remote/cloud storage). Each file gets its own derived key; nothing but the passphrase itself needs to be kept safe. If you lose the passphrase, encrypted backups cannot be recovered.

Transfer settings

Governs how files are grouped into backup archives (live now, not just a preference). Both thresholds have a tolerance band so files only just over/under the raw number aren't needlessly split or clumped:

  • Split: a file only splits into parts (each up to Max size) once it exceeds Max size by more than Split when over by (%) - so with the defaults below, a 2.05GB file stays whole, but anything over 2.2GB splits into ≥2 parts of up to 2GB each.
  • Clump: a file is only eligible to share an archive with other small files once it's smaller than Min size by more than Clump when under by (%) - so with the defaults below, a 195MB file stays on its own, but anything under 180MB can be grouped with other files under that same line into one shared archive (bin-packed up to Max size per archive).
  • Anything between the two effective thresholds is backed up as its own single-file archive, unchanged.

Error handling & retries

If a backup/restore transfer fails, it's retried immediately (short delay between attempts) up to Retry attempts times. If it's still failing after that, it's parked as failed and picked back up automatically Retry interval later - and again after that, until it succeeds or you intervene. This is live now, unlike the settings above.

Cloud storage (Google Cloud)

{% set cs = cloud_storage_config %}

Connect a Google Cloud Storage bucket to use as a second, off-site backup destination alongside (or instead of) a local one.

1. Configure a service account

In Google Cloud Console, create a dedicated service account for MediaBridge (IAM & Admin → Service Accounts → Create), then grant it one of:

  • Storage Admin (roles/storage.admin) at the project level — lets MediaBridge list your buckets so you can pick one below. Simplest to set up.
  • Storage Object Admin (roles/storage.objectAdmin) scoped to a single bucket only — tighter, but MediaBridge can't list buckets with this role, so you'll type the bucket name in manually instead of picking from a list.

2. Get service account credentials

On that service account, create a JSON key (Keys → Add key → Create new key → JSON) and upload the downloaded file here.
